# AGENTS.md

## What this is

CogniX Algo — a Python 3.11 algorithmic trading platform built on FastAPI. Manages multiple symbol instances with Renko-based strategies against the Flattrade/Noren Indian broker API. Single-process app (not a monorepo).

## Run

```bash
python main.py            # starts FastAPI on http://localhost:8000
```

No Makefile, no CI. That is the only way to start the app.

The `/trading` page is a **pre-built bundle** — editing `frontend/**` does nothing until you rebuild:

```bash
cd frontend
npx vite build            # → ../static/trading-app/ (served at /trading)
```

`frontend/node_modules` is already installed; `vite build` takes ~10–15 s.

## Dependencies

```bash
pip install -r requirements.txt
```

One dependency is a **vendored wheel** (`dist/norenrestapi-0.0.30-py3-none-any.whl`) — referenced as a local path in `requirements.txt`. Do not replace it with a PyPI package.

`requirements.txt` asks for `httpx[http2]`; the TOTP token generator (`services/access_token_generator.py`) needs the `h2` package at runtime. If "Generate Access Token" answers 502 *"Using http2=True, but the 'h2' package is not installed"*, the interpreter running `main.py` is missing it — either `pip install h2` there, or run the app from the repo's `.venv` (`.venv\Scripts\python.exe main.py`), which has it.

## Configuration

All config lives in `.env` (loaded via `python-dotenv` in `config/settings.py`). Copy `.env.example` to `.env`. Key values:

- `FT_USER`, `FT_PWD`, `FT_TOTP_KEY`, `FT_API_KEY`, `FT_API_SECRET` — broker credentials
- `FT_ACCESS_TOKEN` — regenerated daily; updated at runtime without restart
- `DASHBOARD_USER` / `DASHBOARD_PASSWORD` — if both set, login is required; if blank, auth is skipped entirely
- `DASHBOARD_TOTP_SECRET` — optional 2FA (generate with `python -m utils.session_auth`)
- `SESSION_SECRET_KEY` — if blank, random key per restart (logs everyone out)

`.env` is gitignored. Never commit it.

## Architecture

```
main.py                     entry point, lifespan, WebSocket route, page routes
api/routes.py               all REST endpoints (prefix /api)
api/openalgo_v1.py          OpenAlgo-compatible adapter (prefix /api/v1) for the /trading sub-app
api_helper.py               low-level Noren broker wrapper (NorenApiPy)
config/settings.py          .env-loaded singleton
database/db.py              SQLite (single `symbols` table, JSON config column)
models/symbol_config.py     Pydantic model — per-symbol strategy settings
services/instance_manager.py  owns all TradingEngine instances, bridges API ↔ strategy
services/access_token_generator.py  headless TOTP-based token generation
services/symbol_index.py    tsym ↔ token index over the 8 scrip-master CSVs (search + resolve)
services/terminal_service.py  order/position/trade/gtt services used by /api/terminal/*
strategy_hub/               managed algo-symbol registry (enable/disable flow, one ExchangeProcess thread per exchange)
services/option_greeks.py   Black-76 IV/Greeks inversion for the option chain
strategy/broker.py          singleton BrokerSession — one shared login + WebSocket
strategy/trading_engine.py  per-symbol engine (runs in its own thread)
strategy/renko.py           Renko brick calculation
ws_broadcast/ws_manager.py  bridges strategy threads → FastAPI async for live UI updates
utils/auth_middleware.py    ASGI session-cookie auth
utils/win_accept_patch.py   Windows proactor accept-loop patch (see Gotchas)
utils/logging_setup.py     console + daily rotating file (logs/cognix_algo.log)
frontend/                   OpenAlgoNew's React source (Vite sub-app, built by hand)
static/trading-app/         `npx vite build` output — served as the /trading page
static/                    vanilla JS frontend (no framework) for /, /trading-legacy
templates/                 Jinja2 HTML (index.html, login.html, logs.html, trading.html)
dist/                      vendored norenrestapi wheel (do not touch)
```

**Key invariant:** `BrokerSession` is a singleton shared by every `TradingEngine`. It owns the single broker login and single WebSocket connection. Feed/order callbacks are dispatched by key (exchange|token / exchange+tsym). Each engine's state is fully independent — only the connection is shared.

**Persistence:** SQLite at `database/renko_platform.db`. Config is stored as JSON blobs so schema changes never require migrations. The `db` module uses `threading.Lock` for thread safety.

**Auth middleware:** Custom ASGI middleware (`utils/auth_middleware.py`) — not Starlette's `BaseHTTPMiddleware` — because it must also gate WebSocket handshakes. Enabled only when both `DASHBOARD_USER` and `DASHBOARD_PASSWORD` are set. `/login`, `/api/auth/*`, and `/static/` are always public.

## Startup sequence

1. `configure_logging()` runs first (console + daily rotating file in `logs/`)
2. FastAPI `lifespan` initialises the database, sets the asyncio loop on `ws_manager`, wires up log/status broadcast callbacks, then calls `instance_manager.load_from_db(autostart_saved=True)` which restores saved symbols and auto-starts any flagged `autostart=True`
3. On shutdown, every RUNNING symbol is stopped gracefully

## WebSocket & live updates

The frontend connects to `/ws` on page load. `ws_manager` bridges strategy threads (which are plain `threading.Thread` daemons) into FastAPI's asyncio loop via `asyncio.run_coroutine_threadsafe`. Strategy code never touches asyncio directly — it calls `on_log`/`on_status` callbacks that schedule sends on the main loop.

**Market data is OpenAlgo websocket-proxy parity (single-process adaptation):**
- `/ws` speaks a client **action protocol**: `{"action":"subscribe","symbols":[{exchange,token}],"mode":"ltp"|"quote"|"depth"}`, `{"action":"unsubscribe"}`, `{"action":"subscribe_orders"}`, `{"action":"ping"}` (→ `{"type":"pong","server_timestamp":...}`). Legacy raw-text keepalives still work.
- Every subscribe action increments a **broker feed refcount per (connection, key)** (`BrokerSession.register_passive_subscriber(exch, token, mode)`); `ws_manager` keeps the per-connection subscription index and **fans `market_data` frames out only to the sockets that subscribed to that `EXCH|TOKEN`** — no more "every tick to every client". Socket drop auto-releases refcounts (`release_on_disconnect`).
- `BrokerSession` maintains a **normalized per-key snapshot cache** (`_md_cache`): partial Noren frames (`tk`/`dk`) merge into the running snapshot (ltp, o/h/l, prev_close from `c`, volume, oi, bid/ask, 5-level depth, tick_size, tsym, derived change%), and every queued WS subscriber gets the cached snapshot instantly, OpenAlgo-style.
- **Feed types per key** follow the OpenAlgo flattrade adapter: Noren touchline (`t`) while anyone is subscribed, plus the snapquote (`d`) only while a depth viewer exists — both can co-exist at the broker; deregistration removes the exact types no longer wanted. `_resubscribe_all_feed_types` replays the full desired state on socket (re)open.
- Engines keep using the raw Noren frame via `register_feed`; UI consumers get normalized frames via `set_tick_listener` / `set_order_listener` (wired in `main.py:_wire_market_data_forwarding`), which fan out as `{"type":"market_data", exchange, token, feed, data}` and `{"type":"order_update", data}`.
- Frontends (charts page module script + dashboard `app.js`) keep a **desired-state map** of their subscriptions and replay it on every reconnect, run a **45s/5s ping watchdog** (quiet ≥45s → ping probes, ≥60s → reconnect), and fall back to **5s `/api/multiquotes` polling** only while the socket is down. The charts page also repaints **live option-chain legs** from `market_data` frames and polls the chain for OI/IV every 30s.

`BrokerSession` has a heartbeat watchdog: if no WebSocket message arrives for 45 seconds during market hours (weekdays 09:15–15:30 IST) while symbols are subscribed, it forces a reconnect with capped exponential backoff (3s → 60s max).

**OpenAlgo `/ws` compatibility layer (what the `/trading` sub-app speaks):** the same `/ws` endpoint additionally accepts OpenAlgo's envelope — `{"action":"authenticate","api_key":…}` → `{"type":"auth","status":"success"}` (the key is ignored; the session cookie already gated the handshake), `{"action":"subscribe","symbol":"EXCH:TSYM","exchange":…,"token":…,"mode":…}` (SINGULAR `symbol` string, unlike the vanilla protocol's `symbols[]`), `{"action":"unsubscribe",…}`, `{"action":"subscribe_orders"}`, `{"action":"ping"}` → `{"type":"pong"}`. Market frames are also emitted in OpenAlgo's shape (`{type:"market_data", data:{symbol,exchange,mode,ltp,…}}`) alongside the vanilla `{exchange, token, feed, data}` frame, and order frames as `{type:"order_update", data}`. `_broker_subscribe`/`_broker_unsubscribe` run through `asyncio.to_thread` — a broker REST/SDK call inline in the WS handler blocks every socket.

**Blocking-call rule (always):** the Noren SDK is `requests`-based and synchronous, and it takes 3–5 s per call when the access token has expired or the broker throttles. Any broker call made from an `async def` handler freezes the whole ASGI loop (no HTTP, no `/ws`, no logs — the app looks hung while the process is fine). Async handlers must go through `asyncio.to_thread` (see `_call()` in `api/openalgo_v1.py`); sync `def` route handlers are already executed in the threadpool by FastAPI.

There is **no pytest suite**. Files in `tests/` are standalone demo scripts that require manual credential setup (editing `usersession`/`userid` values in the script). They are not automated.

## REST API

All endpoints are under `/api` prefix (defined in `api/routes.py`). Key routes:

- `GET/POST /api/symbols` — list all symbols / create a new symbol
- `GET/PUT/DELETE /api/symbols/{id}` — individual symbol CRUD
- `POST /api/symbols/{id}/start|stop|restart` — lifecycle control
- `POST /api/symbols/{id}/squareoff` — manual SQUAREOFF: cancels SL + pending entries, flattens the position with a marketable LMT, then blocks trading until the symbol is stopped and started again (OpenAlgo cmd parity)
- `GET /api/broker/settings` / `POST /api/broker/settings` — access token status / manual update
- `POST /api/broker/generate-token` — headless TOTP token generation
- `GET /api/chart/history` — broker candle history (Noren TPSeries) for the chart desks (`/trading-legacy`'s TerminalFeed; also the shape `/api/v1/history` delegates to)
- ~~`POST /api/chart/watch`~~ — **REMOVED 2026-11-11** with the `/charts` page (refcounted per-tab broker funnel, zero consumers — `services/chart_feed.py` deleted with it)
- `GET /api/optionchain/underlyings` — the full OpenAlgo `all_underlyings`-style universe per derivative exchange from the published Flattrade scrip master (`services/scrip_master.py`; NFO/BFO 2 files, MCX Commodity.csv, CDS Currency_Derivatives.csv). One entry per options-bearing underlying (MCX/CDS keep futures-only names too), indices first, each carrying its nearest futures tsym/token + `expiries[]` + per-expiry representative option tsym/token; disk-cached 12h under `database/scripmaster/`. `?q=` does a case-insensitive substring filter server-side; the charts panel fetches the full list once per exchange and filters client-side (no broker search per keystroke)
- `GET /api/optionchain/chain` — option chain around ATM (`?exchange=NFO&underlying=BANKNIFTY27OCT26F&token=...&count=10&expiry=27-OCT-2026`; `count` = strikes PER SIDE, PiConnect `cnt`, wire returns 4×cnt contracts; pass `&atm=` to skip ATM resolution). `expiry` selects a non-nearest series: the call is keyed on that expiry's representative option tsym from the picker universe (verified live — GetOptionChain returns the tsym's own series). Pipeline: SPEC-verbatim `GetOptionChain` (metadata-only) → board expiry (user-selected `expiry` wins, else one `GetSecurityInfo` on the futures for `exd`, cached — a failed lookup is never cached, so the next load retries instead of serving an expiry-less chain forever) → per-leg quotes (WS `_md_cache` snapshot first, normalized `GetQuotes` fallback with one 0.15s retry, ThreadPool(8)) — **a leg the broker refuses is skipped, never fatal** (the `_safe_leg_quote` wrapper + the `isinstance(snap, dict)` guard in `_fill_leg_quote`: without them a refused quote left `snap` None and `snap.get(...)` killed the whole chain with `Optionchain chain error … 'NoneType' object has no attribute 'get'`, which the panel rendered as an error card) → IV + Greeks inverted/derived locally via Black-76 (`services/option_greeks.py`; theta/day, vega+rho per-1%, rate `FT_OC_INT_RATE` default 0.065) so the first paint is one fast pass. Response adds `expiry`/`int_rate`; legs get `prev_close` + iv/delta/gamma/theta/vega + `greeks_source:"local"` (iv in **percent** — the panel prints it with a `%` suffix; the model works in decimals). ATM resolution takes the underlying's WS `_md_cache` snapshot first (the panel streams it, so no broker call at all) and only then `GetQuotes`, retried 3× (0.3 s / 0.7 s) against PiConnect burst throttling; a futures-keyed call that comes back `No Data` (MCX) is retried once keyed on the nearest expiry's option rep
- `POST /api/optionchain/greeks` — **the Greeks the panel displays.** Body `{exchange, expiry, spot?, legs:[{tsym, token, strike, optt, ltp}]}` → `{stat, spot, spot_source, int_rate, greeks:{TSYM:{iv, delta, gamma, theta, vega, rho, source}}}`. Per leg: invert the market price with the **spot Black-Scholes** model `GetOptionGreek` itself evaluates, then one documented `GetOptionGreek` call at that volatility and take `cal_*`/`put_*`. Legs the broker refuses keep the local values (`source:"local"`); results cached 60s per `TSYM|EXD`. Batched on purpose — each leg is one broker round-trip (~0.3–0.6s solo, ~16s for 40 legs under the live feed), so the panel asks in groups of 8 after the chain has painted and never blocks the first render
- `POST /api/optionchain/greek` — one leg through the official PiConnect `GetOptionGreek` (body `{exd, strprc, sptprc, int_rate, volatility, optt}`, numerics as strings); manual/cross-check form of the batch above
- `GET /api/pichain/chain` + `POST /api/pichain/greeks` — **the standalone "Pi chain" panel's own pipeline, built ONLY on the two documented PiConnect endpoints** (probed live first, `scripts_test/probe_pi_endpoints.py`). `GET /pichain/chain?exchange=&tsym=&cnt=10&strprc=` runs ONE spec-verbatim `GetOptionChain` keyed on ANY scrip of the series (a futures key and an option key answer the identical board — verified live) with the mid = the panel's live WS spot, and returns the metadata rows only (`_normalize_oc_row`; no quotes are composed into the payload — that is the point of the panel) plus `mid`. Missing/blank `strprc` is refused (`Invalid strprc`) and the panel self-heals by seeding one quote. `POST /pichain/greeks` body `{exchange, expiry DD-MON-YYYY, spot, legs:[{tsym, token, strike, optt, ltp}]}` inverts each leg's LIVE LTP with the spot Black-Scholes model GetOptionGreek evaluates (`services/option_greeks.py:compute_leg_greeks_spot`), calls the documented `GetOptionGreek` per leg at that volatility (ThreadPool(8), `_official_leg_greeks`), returns `{stat, greeks:{TSYM:{iv %, delta, gamma, theta, vega, rho, source:"piconnect"|"local"}}}`; legs without a live LTP are never sent. Prices/OI/spot live on the platform `/ws` feed by design — the board itself never touches GetQuotes.
- `GET /api/status` — all engine statuses
- `POST /api/quotes` — normalized single quote (OpenAlgo `/quotes` shape: `bid/ask/open/high/low/ltp/prev_close/change/change_percent/volume/oi/tick_size`; Noren `c` maps to `prev_close`)
- `POST /api/depth` — normalized 5-level depth (`bids[]/asks[] {price,quantity,orders}` + totals)
- `POST /api/multiquotes` — batched normalized quotes `{symbols:[{exchange,token}]}` (≤40), used as the 5s REST fallback while a client's WebSocket is down
- `GET /api/intervals` — candle intervals the chart engine serves (`{code, seconds}`)
- **Trading-terminal routes** (`/api/terminal/*`, serving `/trading-legacy`; `services/terminal_service.py`): `POST /terminal/order` (place: `{symbol, exchange, side: BUY|SELL, type: MARKET|LIMIT|SL|SL-M, qty, product: MIS|NRML|CNC, price, triggerPrice}` → Noren `place_order` kwargs through the shared `BrokerSession`; `_TRADE_LOCK` serializes all writes), `POST /terminal/order/modify` (`modify_order(orderno, exchange, symbol, newquantity, newprice_type, newprice, newtrigger_price)` — SDK arg names verified against the vendored wheel), `POST /terminal/order/cancel`, `POST /terminal/position/close` (opposite-side marketable flat), `GET /terminal/orders|positions` (books normalized to the openalgo-charts `Order`/`Position` shapes — status map COMPLETE→filled, open→working, cancel→cancelled, rejected→rejected; Noren `c`→... `ts` parsed IST → UTC-sec `time`), `POST /terminal/trading-status` (kill switch readback). Transport semantics on every write answer: broker answered+refused → `{stat:"Not_Ok", rejected:true}`; SDK collapsed to None / session / exception → `{stat:"Not_Ok", rejected:false}` (the JS adapter decides BrokerRejection vs PreflightFailure). **Kill switch `CHART_TRADING=0` in .env** blocks all writes (books stay readable); read at call time, but dotenv loads once — a change needs a restart.
- Legacy raw endpoints stay: `/api/get-quotes` (raw Noren). The old `/api/chart/watch` REST funnel was removed with the `/charts` page (2026-11-11).

**OpenAlgo-compatible adapter (`api/openalgo_v1.py`, prefix `/api/v1`)** — the surface the `/trading` sub-app calls. Symbols here are **tradingsymbols** (`RELIANCE-EQ`), resolved to tokens through `services/symbol_index.py` (167 k rows from the 8 published scrip CSVs, disk-cached 12 h in `database/scripmaster/openalgo_symbol_index.json`). Every handler is `async def` and wraps its broker work in `await _call(...)` (`asyncio.to_thread`) — see the blocking-call rule above.

- `POST /api/v1/history` — `{symbol, exchange, interval, start_date, end_date}` → `{status, data:[{time, open, high, low, close, volume, oi}]}`; delegates to `api/routes.chart_history` (TPSeries, and `EODChartData` for `1d`), aggregating W/M from the daily series
- `POST /api/v1/search` / `POST /api/v1/symbol` — scrip-master search (`{symbol, exchange, name, token, tsym, …}`); `symbol` is the full identity (`{brsymbol, brexchange, token, lotsize, tick_size, freeze_qty…}`) via one `GetSecurityInfo`
- `POST /api/v1/quotes|multiquotes|depth` — normalized quote/depth shapes (same builders as `/api/quotes`)
- `POST /api/v1/orderbook|tradebook|positionbook` — books through `services/terminal_service.py`, normalized to OpenAlgo's order/position field names
- `POST /api/v1/placeorder|modifyorder|cancelorder|closeall` — writes through `terminal_service` (honours `CHART_TRADING=0`)
- `POST /api/v1/funds|holdings|margin|syntheticfuture` — **stubs** (empty/last-known; Flattrade exposes no such data cleanly)
- `POST /api/v1/optionchain` — delegates to the existing chain pipeline
- `GET /api/v1/intervals` — the group shape OpenAlgoUI expects (`{seconds:[…], minutes:[…], hours:[…], days:["D"], …}`); a flat list makes the app log `No compatible source for D` and hang on "Loading chart"
- `GET /api/v1/websocket/apikey|config` — WS endpoint/key discovery (the app then dials our `/ws`)
- `GET /api/broker/capabilities`, `/admin/api/timings|holidays`, `/api/v1/market/holidays`, `/alerts/fired|log`, auth stubs — enough shape for the app's boot requests to resolve without errors

## Gotchas

- **The SDK's private WebSocket attributes are mangled `_NorenApi__*`, NOT `_NorenApiPy__*`.** `__stop_event` / `__websocket` / `__ws_thread` are declared on the vendored base class `NorenRestApiPy.NorenApi.NorenApi` (`api_helper.NorenApiPy` only subclasses it), so Python mangles them with the *declaring* class's name. Reading `getattr(api, "_NorenApiPy__stop_event")` always answers `None` — which silently disabled retirement, thread tracking (`_sdk_loop_alive()` was always False) and the stop-event kill switch, so the SDK spawned one `run_forever` loop per reconnect and every one of them hammered the same socket. `BrokerSession._sdk_private(api, name)` resolves either spelling; use it for any SDK internals. `_sdk_stop_events` keeps every Event a start created (each `start_websocket` REBINDS the attribute, orphaning the previous object) and `_stop_sdk_ws_loops()` sets them all.
- **A close that lands within `REFUSAL_WINDOW` (2 s) of `_start_sdk_ws_locked()` is a REFUSAL, not a transient drop.** The broker's `1008` arrives ~0.2 s after connect; the SDK's 100 ms redial then repeats it forever. `_note_ws_failure()` stops the spin on the *first* such close (log: `Websocket handshake refused (closed 0.25s after start)`), and `_reconnect_loop` owns the retries with 3 → 6 → 12 → … → 60 s backoff, 300 s cooldown after 6 failures. Before this, one refusal produced ~10 log lines/second indefinitely.
- **`NorenApiPy.start_websocket()` must never be called while a previous SDK loop is alive.** Each call spawns a NEW `run_forever` thread and re-binds BOTH `__stop_event` (so old loops keep seeing an unset event) and `__websocket` (so every loop drives the same WebSocketApp). Two calls → N threads hammering one socket → `websocket run forever ended in exception, socket is already opened` at ~10/s per thread, which floods the log and starves the ASGI event loop until every HTTP request times out (the app looks "hung" while `main.py` is still running). `BrokerSession._retire_sdk_ws_loop()` sets the live `__stop_event` (all loops share the attribute) and closes the socket before every `start_websocket` — both in `BrokerSession.start_websocket()` and in each `_reconnect_loop` attempt. If the app ever goes unresponsive again, check the log tail for that message first.
- **Never restart a socket the SDK is already retrying.** The SDK's `run_forever` redials every ~100 ms on its own, so `_reconnect_loop` now waits in 0.25 s slices, does nothing while `ws_connected` is True or `_sdk_loop_alive()`, waits up to 10 s for the open callback after a restart, and only then escalates backoff. A forced `start_websocket()` on a healthy session makes the broker answer `1008` (policy violation) to the abandoned session — which then kills the socket we just replaced, so the loop never converges. `_note_ws_failure()` counts handshake failures (5 / 10 s) and sets the SDK stop event so its own spin can't flood the log; after `RECONNECT_MAX_FAILURES` (6) the loop cools down 300 s.
- **Windows: a client abort during `accept()` kills the listening socket** — CPython's proactor accept loop closes the listener on *any* `OSError` from `AcceptEx` (WinError 64 = the client went away mid-accept), which is why the app sometimes looked "hung" with the process alive and `ERR_CONNECTION_REFUSED` on every request (log: `Accept failed on a socket`). `utils/win_accept_patch.py` re-implements `BaseProactorEventLoop._start_serving` to re-arm the listener on that error; `win_accept_patch.apply()` runs at `main.py` import time (before uvicorn creates the loop). If HTTP ever refuses to connect while `python main.py` is running, check for that log line.
- **A Flattrade access token is per-day.** After midnight IST the old token answers `{"stat":"Not_Ok","emsg":"Session Expired :  Invalid Session Key"}` (HTTP 401) and the SDK collapses it to `None` — so `GetQuotes`/`TPSeries` return nothing and the broker refuses the market-data WS handshake with `1008`. Every chart then shows its honest card (`No series returned` / `History request timed out`). Fix: press **Generate Access Token** (`POST /api/broker/generate-token`), which needs `h2` installed in the running interpreter (see Dependencies).
